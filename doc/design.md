# Lanshang 通用设计准则

本文件拥有采用 Lanshang UI 的产品共用的视觉与交互方向，不规定某一个业务页面的布局。AI 接手先读 [前端接入指南](frontend.md)，组件选择、键盘和状态细则见 [组件选择与验收](component-usage.md)，实际尺寸、主题映射与行为以所属 tokens、类型及组件实现核对。

这些规则是公共默认。项目可以在自己的 Design.md 正文中维护明确差异；按其适用范围执行，未声明部分沿用本规范。差异的表达和采用方式见[默认规范与项目差异](frontend.md#默认规范与项目差异)。

展示站本身也是消费者；其目录结构、预览高度、760/1320px 等站点断点和复制源码排版由 [website/Design.md](../website/Design.md) 拥有，不能作为所有产品的默认要求。下述通用表面和方向要求从该文件提取，避免两处维护同一正文。

## 表面与空间层级

Lanshang 使用轻拟物、柔和立体感：浅色灰底承托白色内容卡片，以底色差、留白和柔和阴影表达抬起的表面；细边缘只作辅助，不能用强描边代替层级。卡片保持静止，不因这一规则增加悬停跳动。暗色沿用对应的中性表面明度与轻微边缘，避免浓重投影。

- 工作区底座与结构分栏为平面；需要承托多张卡片时使用共享 `ls-surface-stage`。卡片使用 `BeautifulSurface` 或同一组 `--ls-surface-*` tokens，标题和正文属于同一表面，不额外画一块灰色标题框。
- 导航、树与菜单悬停为灰底；浅色选中为带轻微阴影的白面，暗色为中性灰面。选中项在悬停时仍保持原表面；强调色轮廓只标记键盘焦点，不能当作持续选中装饰。
- 弹窗与菜单属于更高层表面；表单边界、表格数据线、结构分隔线与错误轮廓仍承担各自语义，不把每个单元格、嵌套分区或内联提示都做成悬浮卡片。
- `variant="section"` 明确表示无独立外框的内容分节；实验室各模板保留其独立视觉。消费者必须加载对应版本的共享样式，不在页面覆盖卡片强边框、选中底色或复制公共阴影。


## 当前设计方向

继续维护现有 Lanshang UI，以一致性优化为主线，保留现有 AntD 底座、组件 API、主题与特色组件。实验室和已有对照方案继续保留；HeroUI、coss 或其他框架不作为默认替换目标。整体边界见 [架构说明](architecture.md)。

一致性优先覆盖同语义控件的尺寸、圆角、字体、间距、布局边界、表面层级、悬停与选中、键盘焦点、禁用与加载，以及浅暗主题和窄屏表现。继续遵循视觉优先：图标足以表达的常见操作采用图标并保留可访问名称和提示；对象不清晰、保存或危险确认等需要明确语义的操作保留文字。

整体一致性优先于单个组件的装饰表现。材质效果用于组织层级和反馈交互，同一主题的导航、菜单、按钮与内容表面应共享协调的高光、边缘和阴影强度；避免用彩虹边缘、彩色辉光或强动效争夺内容注意力。选中状态依靠稳定底面和清楚的文字表达，键盘焦点与语义状态仍单独保留。

从真实页面的问题入手，先修共享 tokens、主题适配或所属组件，再让相关页面复用结果；页面 CSS 负责布局，不为相同控件另设一套补丁。同轮修正按影响核对浅暗主题、窄屏及实际交互，保留已有 API、草稿、选择和焦点行为。

21st.dev 用于寻找组件、布局、动效和模板参考；吸收与现有规则协调且来源许可明确的部分。实验样例用于比较和验证，不自动修改默认主题或触发全库迁移。实验室不自动成为正式规范；采纳和发布分别按明确范围推进。

## 组件、尺寸与状态

- 由共享 tokens、Provider 和已安装版本的组件决定字体、圆角、尺寸与状态表面；同语义控件遵循同一约定，页面不能为常见按钮、选择器、分页重新定义另一套默认样式。
- AntD 提供成熟交互，Lanshang 统一视觉及组合约定；可以直接复用受主题管理的 AntD 能力，不要求重复封装全部组件。没有明确需要不引入第二套基础 UI 运行时。
- 信息层级先区分全局导航、工作区上下文、页内导航、工具栏和内容。页签与对应正文保持可见关系，密集数据、媒体画布和品牌登录按各自任务组织，不强制一套布局。
- 悬停、持续选中、键盘焦点、禁用、加载和错误分别表达，不用同一种轮廓替代所有状态。文字及必要状态语义保留，不能仅靠颜色或动画解释结果。
- 真实状态由消费应用提供：首次加载不先展示空结果，刷新保留成功快照，失败有可理解的恢复入口；不因计时结束自动推断成功，也不把未知业务结果当作可直接重发的失败。

## 产品差异与验证

产品可以在 Design.md 中明确品牌标识、局部语义色、内容密度、媒体比例、布局和默认主题的差异；这些差异不能破坏共享控件语义、键盘、焦点或同一产品内部的一致性。当前认可的管理工作台和创作工作室适用范围见 [接入指南](frontend.md#两类已认可的产品参考)。不把一个产品的品牌配色、Dock 或多栏结构强制推广给另一类任务。

验收使用真实主流程及受影响消费者，按变更检查浅暗、目标窄屏、长内容、键盘、加载、空态和失败恢复。具体操作检查见 [组件选择与验收](component-usage.md)；机械检查与浏览器证据分别报告。约定是后续开发的基准，不宣称现有全部页面已符合；截图认可也不代替权限、数据和运行结果验证。

## 后续配色探索的边界

材质、明暗模式和强调色可以分别设计，不把整个页面铺成品牌色，也不以强调色替代成功、警告和失败语义。项目在自身 Design.md 中记录已采用的选择，持续选中、焦点与图片仍保留各自语义。

当前公开入口与本地候选边界见 [主题与配色](theme.md)。多配色和液态玻璃仍属于后续探索，不是当前 main 或 0.2.12 已提供的新 API；主题选择不重挂载业务子树，不清空输入、表格选择或打开的弹窗。

## 品牌家族与图标

平台设计语言覆盖标志、字标、配色、字体、布局、导航、图标、操作和反馈。Lanshang 提供公共规则及可交互范例；平台 Design.md 记录其品牌与业务差异，不要求不同产品复制同一外形。新范例不自动替换原品牌或触发批量迁移，具体见 [品牌与 Logo](brand-design.md)。通用图标以 [图标规范](icons.md) 为单一入口，与品牌资产分开。
