# Lanshang UI 架构与分发

## 当前演进方向

继续基于现有 Lanshang UI 优化一致性，保留 Ant Design 交互底座、现有组件 API、Provider、主题与特色组件。基础控件和视觉规范继续由本仓库维护；后续优先解决真实页面中的共性问题，将修正落回共享 tokens、主题适配或所属组件，再同步示例和直接消费者。

21st.dev 作为组件、布局、动效和模板的参考来源。借鉴或复用时保留来源、许可和必要改动说明，结合现有设计规则按需吸收；不因引入参考而默认增加另一套基础组件运行时或替换现有视觉体系。

实验室继续保留工作台模板、基础视觉候选和其他探索样例，用于对比与验证。实验结论不自动成为默认主题、正式 API 或迁移计划；有明确价值的改进经过组件范围验证后再逐项采纳。当前不推进 HeroUI 或 coss 对现有底座的整体替换。版本发布、Registry 更新与消费者部署仍需分别明确授权；0.2.12 沿用现有底座正式发布一致性优化和工作台模板。

具体视觉与验收规则见 [展示站设计说明](../website/Design.md)。 其中“表面与空间层级”统一拥有底座、浮起卡片、导航选中与浮层的材质约定；消费者通过共享组件和 tokens 接入，不能用局部强描边替代该层级。

## 分层

1. 设计基础：tokens、字体、间距、密度、动效和主题；延续现有 Lanshang 视觉语言与 Beautiful UI 来源，持续优化一致性。
2. 基础组件：展示和基础交互，标准属性、可访问性、受控值及 ref 合同。
3. AntD 适配：复杂表格、表单和弹层保留 AntD 能力；不复制其状态机。
4. 组合区块：列表、详情、侧栏等可修改源码；消费者拥有请求、路由和权限。
5. 文档与分发：API、交互示例、兼容说明、版本化包和区块源码。

## 单一维护来源

基础组件由 @lanshang-labs/ui 版本包维护，业务项目通过升级获取修复。组合区块以源码样例交付，应用复制后自行维护；对上游更新人工比较，禁止自动覆盖定制。区块引用基础包，不复制基础组件实现。

当前区块源码与可运行示例同源，位于 website/blocks.tsx。站点下载时自动转换为 @lanshang-labs/ui 包导入；文件可移入已配置 Provider 和公共样式的应用。区块不依赖站点专用 CSS。示例使用本地数据，不能原样当作业务权限或路由实现。

## API 约定

命名、受控与非受控行为、属性透传、ref、键盘行为在组件文档中说明。视觉变体不推导业务状态。无事件的展示组件保持纯展示；不向公共库加入平台请求、部署类型或权限判断。常规子内容使用 ReactNode；语义标题级别与视觉字号独立。

## 演进顺序

已接入 shadcn 4.21.4 Registry schema 与官方 build/add，见 [安装与验证](registry.md)。通过独立 React 18 / AntD 5 消费者安装主题入口和区块；核心使用站点托管、带内容摘要的 tgz，npm 包尚未发布。CLI 不自动修改应用入口；复制后的源码由消费者维护。

## 验证与发布

组件单测、文档类型检查、静态站构建、包内容检查、真实平台消费者和独立项目验证分层记录。明暗主题与窄屏应可操作。线上站点发布与 npm 发布分别授权；未验证的 React 19、AntD 6、SSR 不进入兼容承诺。

## 增量组合实验

现有根入口、Provider 和全局样式保留兼容。新增可选媒体入口 `/media` 与 `/media.css`，让 ImageCard / ImageDeck 在不装载旧全局主题的情况下复用宿主 AntD；模板通过局部语义变量决定材质。见 [独立媒体接入](media.md)。此入口自 0.2.12 正式提供。

实验室模板可复用来源明确、许可保留的成套视觉实现，模板拥有其局部页面层级和整体样式；AntD 提供成熟交互，Lanshang 特色组件探索独立接入。第一份接入为 ShadcnStore 实验的 Resources，原模板与局部玻璃材质共用交互。这是保留的组合实验，不改变现有基础 UI 的维护方向；先形成可验证样例，再决定是否吸收局部改进，不为每套视觉创建一套基础控件。


Dock 正式源码使用独立 `/dock` 与 `/dock.css` 子路径，Motion为optional peer，根JS入口不导入。组件仅拥有距离动效、焦点移动和展示；路由、权限、activeId采纳与动作由消费者拥有。可继承Provider变量或使用局部主题，无隐式全局样式/存储。实验室保留并复用正式实现，来源MIT随包保留；自 0.2.12 发布，见[接入指南](dock.md)。

## Dock 工作台组合模板

`WorkspaceLayout variant="dock"` 和 `WorkbenchPage` 属于通用展示层，详见 [Dock 工作台模板](workbench.md)。前者拥有侧栏、顶栏、主区与 Dock 的空间关系；后者拥有工具栏、页签区域、内容面板与状态栏的共同外观。两者都不依赖 Motion：Dock 由消费者通过 footer 插槽选择性传入，保持可选 peer 边界。业务项目只组合数据、权限、原生路由及业务操作，不复制模板公共边框、阴影或尺寸规则。本轮随 0.2.12 发布，原实验室保留。
