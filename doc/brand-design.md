# 平台品牌与 Logo 设计

Lanshang 拥有公共设计语言和可复用范例；消费平台拥有产品名称、品牌身份、原资产及最终采用决定。统一体验覆盖标志、字体、配色、导航、内容密度、反馈和交互，不止替换 Logo。品牌不要求所有产品使用同一布局或同一标志。

## 本地候选范例

本地品牌探索以 Workspace、Studio、Console、Docs 四类产品，以及符号、叠层和字母 L 三类标志比较平台设计语言。其 `/#/patterns/brand-design` 页面和相关源码尚未随本次文档交付，不能据此认为当前 main 或公开文档站已有该入口。使用时先核对实际 checkout；没有对应页面时，仍可按下面的规范记录自己的品牌与差异。

这些是范例，不替换现有 Lanshang 标识，也不是 DRAMA 或 Boomerang 已采用的正式 Logo。页面中的登录仍为构图示意；工作台与状态对照页提供本地交互，不伪装接入业务服务。

## 平台设计语言的最小内容

| 内容 | 应明确的决定 |
| --- | --- |
| 产品定位 | 为谁服务、主任务是什么、平台之间的关系 |
| 标志与字标 | 主版本、单色、反白、应用图标、最小尺寸和外围净空 |
| 色彩 | 默认界面配色、品牌识别色、不可改写的语义色；品牌色不必涂满所有控件 |
| 字体与密度 | Provider 字体、三档控件、正文／标题层级、数据或媒体密度 |
| 布局 | 管理工作台、创作画布、资源控制台或文档阅读，选择已有模板组合 |
| 图标与操作 | 同一语义同一图形，图标按钮有名称，含糊或危险操作保留文字 |
| 反馈与恢复 | 首次加载、刷新保留、空结果、失败和未知结果分别表达 |
| 跨端 | 窄屏导航、点击范围、键盘和减少动态效果 |
| 交付 | SVG 来源／许可、采用的固定版本、原生验证入口和实际采用证据 |

本地范例不做商标可注册性或全尺寸光学认证；16px 应在目标浏览器和实际应用图标中复核。平台特色插画、应用商店资产及启动屏按实际需求补充，不把它们混入通用操作图标。

## 现有产品如何收敛

1. 核对平台事实：技术栈、包来源、已有 Logo、主题、主要用户和操作密度；先保留原资产。
2. 选择共享规则和布局类型，记录有理由的业务差异；从一条真实主流程做候选对照。
3. 把共性缺口修回 Lanshang，把平台品牌选择写入自身 `Design.md` 正文。无需增加 devctl 配置字段或风格状态机。
4. 验证目标页面浅暗、窄屏、输入／选择保留、Portal、错误恢复和真实业务语义，再按固定依赖升级。
5. 发布公共包、消费者采用、线上部署分别记录，不从范例认可推断为全平台已采用。

开发流程见 [AI 前端工作流](frontend-workflow.md)，图标来源与语义见 [图标规范](icons.md)。
